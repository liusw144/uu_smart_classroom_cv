# Harness 与项目生产就绪评估

评估日期：2026-11-02。远端提交：b4762b0cdadc1e1a6fca3bb4958e1a9dfa85c621，提交说明 cc。

## 结论

项目当前不具备生产上线条件。现有 Harness 可用于约束 AI 开发、运行工程检查及登记验收材料，但尚不足以自动判定生产可用或自动放行发布。

此前生成的范围是 M0 工程基础。目录、约束、构建和部分测试已经落实；模型、完整业务与运行验收仍需要逐项实现和验证。CI 成功表明当前检查通过，不能代表尚未实现的能力存在。

本次未修改应用、门禁、生产阻塞清单或 CI 配置，没有新增提交或推送。仅新增评估文档；合成材料验证在临时目录中进行，未写入项目验收目录。

## 当前阻塞项

生产门禁实际列出以下事项：

1. 真实模型及行为规则未接入与评测。
2. 教学业务、持久作业与边缘节点协议未完成。
3. 生产节点 mTLS、登录限流与完整审计未完成。
4. 四种部署模式、数据库恢复与容量验收未完成。
5. 缺少 harness/release-evidence.json。

这些不能通过补一个 JSON、修改就绪返回值或清空阻塞数组解决。需要真实图片闭环、节点执行、异常恢复、学校隔离以及现场算法与硬件测试。

## Harness 的具体不足

### 验收材料检查尚未核验事实

scripts/quality_gate.py 的 production_errors 当前只检查阻塞数组、六类材料路径是否存在，以及文件 SHA256 是否一致。它不运行真实模型、不执行负载或恢复测试，也不核验材料正文是否是有效测试报告。

本次在临时目录中放入六个普通文本文件及匹配的哈希，并使用空阻塞清单，该函数返回零错误。这个结果说明当前检查是材料完整性检查，不能独立证明材料的内容或生产结论真实。该限制在现有发布文档中也要求由人工评审补足。

代码位置：[production_errors](https://github.com/liusw144/uu_smart_classroom_cv/blob/b4762b0cdadc1e1a6fca3bb4958e1a9dfa85c621/scripts/quality_gate.py#L56)。

### 缺少发布版本与证据的强绑定

检查器没有强制验证提交 SHA、目标镜像 digest、模型/规则/数据集哈希、测试环境、运行时间与 CI run ID 的一致性。旧报告的哈希可以保持正确，但不一定对应即将发布的代码与镜像。

应建立结构化证据 Schema，并将报告绑定到具体候选版本；同一已验证镜像进入预发布与生产，避免验证后重新构建出不同产物。

### CI 没有执行生产发布门禁

当前提交的 CI 运行基础门禁和各模块验证，没有执行 --production，也没有预发布部署、生产环境审批和真实运行验收任务。四个绿色任务属于工程验证，不构成生产发布授权。

此外，本地已暂存删除 CI 文件，当前基础门禁仍能通过，因为它不要求工作流文件存在。如果该删除被提交，当前这套仓库工作流将从后续提交中移除。本次未恢复、取消暂存或提交用户的这项改动。

### 运行环境证据仍不完整

目前没有核实生产镜像构建与扫描、实际模型推理、GPU/CPU 容量、网络断开恢复、数据库备份恢复、灰度与回滚、持续监控和证书轮换。隔离数据库上的登录集成成功，不能替代上述测试。

## 建议的下一阶段

先保留或确认 CI 的处理方式，再按以下顺序推进：

1. **强化 Harness：** 强制检查 CI 与必要验证入口；定义证据 Schema；绑定提交、镜像、模型和环境；通过受控 CI 生成证据，保留人工发布确认。
2. **实现最小真实业务：** 完成学校隔离的教学任务、素材、持久作业、节点身份与真实图片检测闭环，覆盖失败、重复、取消与越权情况。
3. **建立预发布验收：** 在约定环境部署固定镜像，执行契约、端到端、异常、隔离、真实算法和容量测试，保存可复核报告。
4. **验证运行保障：** 演练备份恢复、模型与应用回滚、节点离线重连、密钥/证书轮换，形成监控和故障处理记录，再评审具体生产版本。

生产门禁应对每个候选版本给出“通过、失败、未验证”，未验证不能自动算通过。现阶段可继续用这套 Harness 开发和检查工程，不能据此直接宣称可生产上线。
