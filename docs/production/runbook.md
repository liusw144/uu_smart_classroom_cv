# 运维与恢复手册基线

故障排查先区分业务接口、数据库、Redis、节点网络、模型和素材存储。使用 request_id、学校、任务与节点编号关联日志；日志不存密码、令牌、原始帧和学生素材。

健康检查：Java 存活与就绪分开，Redis/数据库失败使就绪失败；FastAPI 模型缺失时就绪失败。边缘阶段另补心跳、磁盘水位、排队、租约过期和回传延迟指标。

备份：数据库全量与增量、对象清单和配置分开留存；恢复到隔离环境，核对学校隔离、数据版本及素材引用后才可记为恢复成功。备份文件存在不能当作恢复演练完成。

升级：先备份与验证向后兼容迁移，灰度应用，再灰度模型。模型与规则各有版本及哈希，出现质量回退可切回已验证组合；数据库破坏性迁移不能假定能用旧镜像回滚。

生产 RPO/RTO、并发、抽帧率和告警阈值在硬件试点明确，目前没有测量值，不给出默认承诺。
