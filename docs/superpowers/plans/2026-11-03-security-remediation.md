# 三项安全边界修复实施计划

目标：修复扫描确认的登录预算、素材累计配额及视频解码资源边界，按生产防护要求验证；本次不代替整个系统生产验收。

依据：2026-11-03安全扫描三项中危发现及只读修复前调查。用户已明确要求继续修复，在既有根目录原位实施，由当前执行者逐项实现，不自动提交、推送或部署。

边界与决定：

- 登录：应用层预算端口，Redis Lua原子限制全局、连接来源及账号尝试，分布式租约和本进程并发槽保护BCrypt；Redis异常失败关闭。仅预算键做Unicode归一化，不改变账号查询；不信任调用者转发头。
- 素材：配额按服务端确定的素材负责人计费，管理员代传规则保留；学校、负责人及全局同时限制字节和数量。新增迁移，PENDING素材、READY素材和待清理文件都计费。删除先通过引用约束，持久清理账本确认物理删除后才释放。文件锁与状态核对阻止暂停上传和回收竞争；旧迁移不改。
- 视频：整个视频作业在独立进程中运行，重型导入及媒体打开前完成限制。Windows采用Job Object总内存及进程树回收；Linux采用进程组、地址空间/CPU硬限制，并明确它是每进程预算。父进程总截止时间覆盖解码、推理和FFmpeg管道。结果仅在子进程成功、大小/身份/哈希复核后发布，临时目录失败清理。
- 当前源码、依赖和本机数据库继续隔离；中文注释；真实模型缺失仍不可用。保留既有文档改动及生产阻塞。
