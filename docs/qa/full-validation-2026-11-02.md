## 已复现问题

6个失败测试对应以下4组根因，不能按6个独立缺陷夸大。

### F01：生产证据门禁只检查文件与哈希

优先级P1，影响发布判断。`scripts/quality_gate.py:56` 的 `production_errors` 接受6类证据路径及SHA256，却没有检查内容结构、测试结果、提交、镜像、模型或时效。本轮仅在临时目录创建6份明确写着“未执行验收”的普通文本，并把阻塞列表设为空，函数仍返回空错误列表。未在真实项目伪造任何生产证据。

复现：`test_plain_text_files_are_not_enough_for_production_evidence`。预期拒绝占位材料，实际接受。哈希只能证明内容未变，不能证明其为有效验收。建议由受控CI产生结构化证据，校验具体Git SHA、镜像digest、模型和数据版本、环境、执行命令、退出码、JUnit/测量结果及发布策略；生产判定不能由AI填写一个通过字段完成。

### F02：架构检查可被完全限定类型引用绕过

优先级P2。`scripts/quality_gate.py:22` 仅匹配Java的import语句。临时领域类 `class Bad { org.springframework.context.ApplicationContext context; }` 没有import，扫描结果为空。复现：`test_architecture_boundary_covers_fully_qualified_spring_type`。

建议以编译后依赖验证替代Java框架import正则；保留廉价文本检查作为辅助。不能因现有扫描通过就宣称领域层所有依赖均合规。

### F03：异常字符Bearer凭据触发500

优先级P2，影响异常输入的可靠拒绝。`fastapi/src/classroom_vision/api/routes.py:18` 将请求凭据作为字符串传给 `secrets.compare_digest`，非ASCII值触发异常。本轮用TestClient原始请求头 `Bearer \xc3\xa9` 复现500和明文Internal Server Error，而非400/401/403。

复现：`test_non_ascii_identity_is_rejected_without_server_error`。建议明确凭据编码/字符集，非法字符统一拒绝，比较有效输入的字节，并补真实ASGI服务验证。该结果是TestClient层复现，未据此宣称生产网络可达漏洞。

### F04：真实错误体与OpenAPI不一致

优先级P2。检测接口实际返回401、422和503，OpenAPI只声明200及默认422；默认422的detail模型也与实际error封装不同。参数化测试3项均失败。`fastapi/tests/test_contract.py` 只核对生成快照与已提交快照，两边可能同时缺少真实错误定义，因此保持绿色。

复现：`test_actual_error_envelope_is_documented[401/422/503]`。建议统一错误模型、显式声明响应，再用真实请求结果校验对应schema；同步更新快照和调用方类型。

### F05：本地CI文件删除未被基础门禁发现

本次审核开始前，`.github/workflows/ci.yaml` 已是用户暂存删除状态，保持原样。当前foundation门禁仍通过，因为required清单不要求任何CI入口。远端旧提交绿色不能证明下一个删除CI的提交仍受保护。建议把必需工作流及测试发现检查纳入门禁，并检查仓库分支规则；本轮未改变CI或远端设置。

## Harness效果不佳的具体原因

1. `tasks/backlog.json` 只有粗粒度里程碑，未和28个功能、18个验收场景及可执行测试逐项绑定。
2. 单元测试与快照验证的是已有基础实现；缺失业务没有对应失败验收，绿灯容易被误读为产品完成。
3. 根验证命令不运行真实浏览器与数据库全链路，也不校验模型质量、断网和恢复。
4. 门禁含文本正则和材料存在性判断，缺少针对门禁自身的反例测试。本次已证明两处绕过。
5. 运行失败、功能未实现、环境不可用和成功通过没有统一机器状态；AI能写记录，却没有独立执行结果驱动状态。

应先将本轮4组复现转成受控回归，再给首个真实业务闭环建立E2E；增加规范文件数量或让多个AI重复阅读文档不能代替这些工作。
