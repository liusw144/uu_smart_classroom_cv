# 校内试点基础完善设计

用户已同意按完善建议推进，并明确本轮不访问实体摄像头。沿用既有统一代码、Java/Sa-Token、Vue、FastAPI、独立edge架构，在用户指定项目根目录原位实施；不改生产就绪结论，不自动提交或推送。

实施方向：优先补可以客观验收的持续验证、节点活性/续租、全片采样与安全恢复，并交付设备和标注工具。与一次性重构全部生产部署相比，这一方向保留已验证链路，能给下一次试点提供可检查的结果。现有架构与用户接受的推进顺序是本轮依据，以下实现参数由执行者确定。

1. CI：最小权限、固定动作版本，独立模块构建/测试、真实MySQL/Redis隔离联调、无模型核心浏览器回归；权重/完整AI演示单独本机验收，不把CI未执行写成远程通过。门禁检查工作流存在，统一最新状态入口。
2. 活性：节点最近90秒有认证请求才可分配；领取与租约心跳更新活性。学校管理员只看本校节点状态，不返回密钥。节点断网不能被当作在线。
3. 续租：edge推理异步执行，主线程每30秒尝试续租并持久化新到期时间；网络失败保持已有Outbox，旧/取消租约不能提交新结果。已完成待确认结果仍向Java尝试幂等确认，最终由服务端判断租约。
4. 视频：保持30秒/32MB/32帧资源边界；长视频将采样点均匀分布全片，包含首尾可解码帧。结果明确采样策略与覆盖区间，不承诺逐帧分析；短视频保持原有采样口径。
5. 恢复：维护窗口停业务写入后备份业务库和素材/产物，哈希清单；只恢复到本脚本新建、随机命名的隔离库，绝不覆盖现有库。验证数据内容摘要及文件完整性，不将数据库备份或凭据作为交付公开文件。
6. 设备：仅提供显式运行的授权摄像头/RTSP采集工具，凭据来自本地配置；有超时/帧数上限，默认不打开设备。用本机生成的视频输入验证采集工具，实体设备状态仍标未验收。
7. 课堂标注：提供数据集清单、类别约束、学校/拍摄批次分组划分、标注格式检查和评测说明；没有人工标注时不得输出准确率。

验收：旧业务回归不退步；离线与重启仍有效；离线节点不分配、跨学校节点状态拒绝；模拟较慢推理期间真实续租；12秒以上公开视频衍生片覆盖到末尾；备份恢复到全新库并核对内容；采集只用文件；文档与代码不再矛盾。生产mTLS、真实课堂精度、长期现场容量与四模式生产部署仍另需真实证据。
