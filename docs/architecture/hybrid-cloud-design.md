## 2. 目标、首期范围与边界

目标是建立可扩展至生产的工程基础，先跑通一个真实、可追溯的业务闭环，再按证据开放全部功能和部署模式。

首期闭环：登录 → 学校与教师权限 → 班级/课程/课堂任务 → 上传图片 → 持久化检测作业 → 指定边缘节点执行 → 保存结果 → 统计与模板报告 → 审计及导出。随后增加批量图片、视频和摄像头，不能用静态页面或固定检测结果代替真实闭环。

最终业务范围继续包括教师端、管理端、公告、类别与模型档案、配置、操作日志、AI 分析、PDF 报告，以及图片/视频/摄像头检测。首期不承诺人脸识别、学生身份识别、跨镜追踪、学习效果评分或自动教学考核。没有跟踪与去重设计时，检测次数不能称为学生人数。

生产交付需要实际模型、标注样本、硬件基准、隔离测试和运行演练。代码生成完成只是进入验证阶段。

## 3. 方案比较与用户选择

| 方案 | 优点 | 代价与适用性 |
| --- | --- | --- |
| 各部署模式分别开发 | 可针对单一场景快速定制 | 四套逻辑易分叉，权限与算法难保持一致，不采用 |
| 所有素材集中上传云端推理 | 集中运维与资源调度较简单 | 依赖带宽与授权，断网无法处理，不适合作为全模式默认 |
| 统一业务控制面＋可独立部署的边缘执行面 | 同一版本支持本地、私有、云端和混合部署，素材可留校 | 增加节点身份、任务租约、结果幂等和离线同步；用户已选择 |

统一代码并不意味着同一数据库在云端与校内双向写入。每个安装实例只有一个权威业务控制面；不同学校独立安装后的跨实例数据迁移另设协议，不直接做 MySQL 双主同步。

## 4. 部署模式与功能承诺

| 模式 | 控制面位置 | 推理与素材位置 | 网络断开时 |
| --- | --- | --- | --- |
| 单机 | 同一台开发机或工作站 | 本机边缘服务、本机目录/对象存储 | 无需公网；外部 AI 不可用时使用模板 |
| 校内私有 | 学校机房/私有云 | 校内 GPU/CPU 节点及存储 | 校内网络正常即可完成完整业务闭环 |
| 云端 | 租户授权的云环境 | 云端执行节点与对象存储 | 依赖到该控制面的网络；支持云厂商适配 |
| 混合云 | 云端业务控制面 | 校内节点、校内原始视频；按策略上传统计/报告 | 已领取作业可在租约规则内继续计算并缓存；新业务操作默认停止 |

混合云断公网时不保证完整教务后台可用，也不提供无限期离线登录。如果要求学校在断网时继续新建课程、登录和创建新任务，应部署独立校内控制面；它与云端的业务联邦属于后续扩展，不在首期自动双向同步。

建议生产运行在 Linux 容器；Windows 保留开发和经验证的 CPU 单机运行配置。支持模式表示交付目标，只有在对应模式通过端到端测试后才标记为已支持。单机 Compose 本身不提供生产高可用；云端高可用与私有化单节点使用不同资源配置。

## 5. 服务职责和调用边界

```mermaid
flowchart LR
  U[教师端与管理端 Vue] -->|HTTPS＋Sa-Token| J[Spring Boot 业务控制面]
  J --> DB[(MySQL 权威业务数据)]
  J --> R[(Redis 会话与缓存)]
  J --> C[可选云对象存储]
  E[校内边缘 Agent] -->|主动出站 mTLS：领取任务／心跳／回传| J
  E --> F[FastAPI 推理入口＋有界 Worker]
  F --> O[ONNX Runtime YOLOX＋RTMPose＋规则]
  E --> L[(校内素材与持久化 Outbox)]
  U -->|校内可达＋短时素材授权| G[边缘素材网关]
  G --> L
```

Java 负责学校、用户、会话、权限、教学数据、任务调度、统计口径、报告与审计。FastAPI 负责模型生命周期、检测契约、输入校验、健康检查和推理适配。边缘 Agent 是持久化任务执行进程，负责出站连接、租约、下载/定位素材、恢复与回传。FastAPI API 的进程退出不能导致业务作业记录丢失。

混合云媒体通道调整旧文档“所有帧先经过 Java”的示例：业务控制仍只访问 Java；原始视频在校内网关进入边缘节点，避免绕行云端。跨公网实时观看不是首期默认能力；后续如需要，加入经授权的媒体中继，不以开放边缘端口替代。

建议采用模块化 Java 单体、一个 Python 代码库中的 Agent 与推理进程、共享组件的 Vue 双入口，避免在首期拆出大量独立微服务。Java 业务数据库不由 Python 直接访问。

## 7. Sa-Token、租户与资源权限

用户会话为 Sa-Token 管理的服务端会话；不因为头为 Bearer 就假定是 JWT。建议仅从 Authorization 头读取，访问令牌不放 URL，不在日志中记录。密码用 BCrypt，Sa-Token 不负责代替密码哈希。生产密钥和管理员初始密码由部署流程生成，不复用公众号演示账号。

建议用户会话绑定一个学校上下文。若一个账号属于多个学校，由服务端验证成员关系后建立或切换上下文，并使旧上下文凭据失效；租户不从可任意修改的请求字段直接采信。

| 身份 | 权限边界 |
| --- | --- |
| 平台运维 | 节点健康、租户开通、版本管理；默认不能读取学校素材与课堂内容 |
| 学校管理员 | 本学校用户、教学数据、节点、策略与审计 |
| 教师 | 本学校且本人拥有/被明确授权的班级、课程、任务、素材、报告 |
| 边缘节点 | 仅绑定学校与节点允许领取的作业，不持有人类管理员权限 |

权限判断依次校验会话、动作权限、学校范围、资源归属。Sa-Token 管动作权限；资源归属必须落实到查询和更新条件。查询、导出、统计、批量操作、下载签名、对象路径、缓存键和异步回调都需要 tenant_id。MyBatis 租户插件只是防线，手写 SQL 与绕过插件的管理逻辑要单独检查。

建议关键表含 tenant_id，涉及学校内实体引用时用复合唯一键/外键，防止不同学校课程、任务、素材串联。节点身份映射 tenant_id 与 node_id，以证书登记信息为准，不采信节点在 body 自报的学校。返回其他学校资源统一按接口规则 404，已知动作权限不足为 403，未登录为 401。

平台支持访问学校数据如确有需要，应有学校授权、时限及审计，不提供默认跨租户超级管理员查询。

## 8. 节点身份与离线行为

建议使用一次性、短时效的节点注册凭证绑定学校，注册后签发每节点独立证书，以 mTLS 连接控制面；支持撤销、轮换和到期告警。运行时不共享全平台固定 X-Service-Token。单机开发可使用明确标注的开发认证配置，生产启动应拒绝该配置。

学校节点主动出站访问控制面，避免要求学校开放公网入站端口。云端会话 Redis 不穿透到校内，不在公网共用一套 Redis。心跳只报容量、版本、队列、磁盘和错误摘要，不夹带原始帧。

断网时：已接收任务可以保留本地计算结果，但不能自行延期云端租约。重连后先续租/重新领取；旧租约结果不得直接覆盖新一次执行。若要复用缓存结果，节点在拿到新租约后需验证相同输入哈希、模型/规则与参数版本，再按新租约回传。

离线新登录、角色变更、新管理指令默认不可执行。撤销在节点离线期间无法即时传达，因此本地素材授权只允许短时效；如果要求立即撤销，素材访问必须在线核验。边缘 Outbox 有磁盘配额和告警，达到阈值暂停领新作业，不能无限缓存。

## 9. 作业协议与恢复规则

持久作业在 MySQL 中与业务任务事务一致地提交，返回 202 与 job_id。事务 Outbox 用于后续通知/审计事件；第一阶段节点直接拉取作业，避免把 Python Celery 消息格式暴露为跨语言公共协议。后续如引入 RabbitMQ/Celery，只做局部加速与执行，权威状态仍在业务数据库。

状态建议：QUEUED → LEASED → RUNNING → SUCCEEDED；可重试错误进入 RETRY_WAIT 后重新排队；不可重试错误或超过上限进入 FAILED；取消先进入 CANCEL_REQUESTED，再由执行端确认 CANCELLED；未领取任务可直接取消。

| 协议项 | 建议规则 |
| --- | --- |
| 领取 | 事务内选取匹配学校、节点能力、优先级的可运行作业；行锁竞争保证单个有效租约 |
| 租约 | 使用服务端时间；建议初值 120 秒、每 30 秒续租；计算任务按检查点响应取消 |
| 防止旧执行覆盖 | 每次领取递增 attempt_no，生成随机 lease_token；续租/进度/结果均校验该组合与节点绑定 |
| 超时 | 租约过期后可重领；迟到的旧结果返回 409，不将旧执行标成功 |
| 重试 | 网络/临时资源错误指数退避＋抖动，建议最多 3 次；无效输入或模型不兼容不盲目重试 |
| 创建幂等 | tenant_id＋请求幂等键唯一；同键不同请求哈希返回 409 |
| 结果幂等 | 同一作业/attempt/result_id 和结果哈希重复提交返回原回执；同键不同哈希返回 409 |
| 取消竞争 | 取消与成功提交在服务端事务中串行裁决；取消请求已生效时拒绝新的成功提交；已成功后返回当前终态 |
| 重启 | 节点从本地数据库恢复待回传内容；控制面根据租约扫描恢复，不依赖单进程内存 |

参考业务接口：POST /api/v1/auth/login、GET /api/v1/auth/me、POST /api/v1/tasks、POST /api/v1/assets、POST /api/v1/tasks/{id}/jobs、GET /api/v1/jobs/{id}、POST /api/v1/jobs/{id}/cancel、GET /api/v1/tasks/{id}/summary。

参考边缘接口：POST /edge/v1/claims、POST /edge/v1/jobs/{id}/renew、POST /edge/v1/jobs/{id}/progress、POST /edge/v1/jobs/{id}/complete、POST /edge/v1/jobs/{id}/fail、POST /edge/v1/nodes/heartbeat。节点身份由 mTLS 认证上下文提供，不接受浏览器 Sa-Token 代用。

结果 envelope 必须含 schema_version、job_id、attempt_no、lease_token、result_id、input_sha256、model_version、rule_version、参数版本、采样配置、耗时、有效样本量和结果清单；服务端重验租户归属、输入、版本与产物，再提交终态。外部输入不能携带任意服务器文件路径或远程 URL。

## 10. 素材、数据与模型契约

跨服务统一使用 asset_id，不把 D 盘路径或云 URL 当公共接口。素材记录含 tenant_id、存储域、node_id/region、对象键、大小、哈希、媒体类型、保留策略和生命周期状态。边缘本地目录映射只在该节点配置，S3 对象键由服务端生成；下载由鉴权网关或短时签名授权。

混合云默认原始视频留在校内，上传统计、模型版本和必要审计；报告与可视化图片是否上云分别配置。学校开启云推理时明确切换数据策略。云端不能因存在 asset_id 就假定自己能读取校内文件。校内素材在浏览器到校内网关的链路访问；远程不可达时界面说明该素材当前不可访问。

建议表族：tenant、user、tenant_membership、role、permission、role_permission、classroom、course、course_teacher、lesson_task、asset、detection_job、job_attempt、detection_result、behavior_aggregate、analysis_report、edge_node、node_certificate、model_release、audit_event、outbox_event。正式字段、索引与迁移在实施计划内生成并评审。

模型发布清单必须包含权重 SHA256、来源与许可、输入尺寸与颜色顺序、归一化、关键点映射、输出解码、行为规则与阈值版本、支持的 execution provider、最小节点版本、基准测试集与结果。未取得真实权重时只提供明确标注的开发适配器；生产模式不得用 mock 推理启动。

ONNX Runtime GPU 依赖应按官方 CUDA/cuDNN 兼容表锁定，不自动安装“最新 GPU 包”。节点注册自身 CPU/GPU/内存和编解码能力；无法满足模型要求时不领任务或明确拒绝，不静默退化并伪报性能。[ONNX Runtime CUDA 要求](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html)。

FastAPI 入口不把整段视频放在 BackgroundTasks 中当作持久任务队列。推理 Worker 使用有界并发，模型通过生命周期加载；初始每 GPU 一个受控模型进程，再根据实测扩容。[FastAPI 后台任务说明](https://fastapi.tiangolo.com/tutorial/background-tasks/)。

## 11. 统计、算法及报告

检测链路：校验媒体 → 解码/抽帧 → YOLOX 定位人员 → 人体裁剪和坐标映射 → RTMPose 关键点 → 可解释规则 → 帧/时间统计 → 产物保存。保留抽帧时间戳、有效帧数、有效关键点比例和规则版本，确保结果可复算。

抬头/低头/写字/读书等几何规则需要允许 UNKNOWN/低置信/未分类，不能强制所有人归入六类。读书与写字姿态相似，必须在真实课堂标注集验证；关键点置信度不等于行为分类准确率。互斥标签与可并存标签的统计在契约中区分，口径以规则版本记录。

时间比例使用采样时间权重及有效检测分母；目标出现次数使用累计检测口径。唯一学生数、出勤率和个人轨迹不从上述统计推断。摄像头丢帧、遮挡与空画面要在报告标明覆盖度。

模板报告为默认可离线能力，外部/本地大模型为插件。默认只发送经学校策略允许的聚合数据；生成内容标注依据、时间和模型版本，不能凭空增加检测事实。AI 不可用时保留检测与模板报告闭环。PDF 导出需字体、中文排版、鉴权与下载过期验证。

## 12. 资源、运维与可观察性

不能仅凭文章给出“支持多少教室”承诺。先实测解码、YOLOX、人数×姿态计算、规则、编码与传输各阶段，分别记录 CPU/GPU、内存/显存、吞吐和 P95 延迟。

容量估算：每秒推理需求≈视频路数×抽帧率；单帧成本≈检测成本＋平均人数×姿态成本；平均执行并发需求≈作业到达率×平均作业时长。留出解码、突发与故障余量后确定节点数，不能把单人推理 FPS 当整间课堂吞吐。

文件容量：存储量≈输入码率×保存秒数÷8×保留天数对应的录像数量，另计标注视频、图片与报告。例如 4 Mb/s 视频每小时约 1.8 GB（十进制、不含副本和产物），实际按码率测量。保留期、删除任务、Outbox 配额都必须可配置。

指标至少包括 API 错误/P95、租约过期、重试、排队时长、节点在线率、磁盘水位、模型加载、推理吞吐、有效检测覆盖度与报告失败。日志关联 tenant_id/job_id/request_id，敏感凭据和原始帧不写日志。

生产交付应包含：密钥注入与证书轮换、数据库迁移、备份恢复、对象与数据库一致性、灰度模型回滚、镜像与依赖清单、健康检查、告警、容量扩展、故障处理手册。RPO/RTO、并发量和可用性目标在现场验收前与实际预算及硬件一起确定，不能在本文中默认保证。
