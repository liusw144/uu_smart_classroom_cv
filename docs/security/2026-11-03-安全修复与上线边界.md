# 安全修复与上线边界

日期：2026-11-03。对应任务：SECURITY-REMEDIATION-20261103。对应原扫描：5ff3c623-5e5c-44b3-b2ce-c3b129992102。

本文记录登录预算、素材累计配额和视频进程隔离的修复。原扫描为部分覆盖，修复三项问题不能作为整个系统安全认证或生产发布批准。生产模式的拒绝启动和生产门禁继续有效。

## 登录预算

登录在查询账号和BCrypt校验前，先经过Redis原子准入及本机并发信号量。学校与账号输入的NFKC摘要用于预算，不改变实际数据库查询；找到账号后再核验真实账号编号预算，防止数据库等价字符串分散计数。未知账号仍执行一次虚拟密码哈希校验，避免账号枚举时序差异。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| LOGIN_BUDGET_NAMESPACE | uu-login-v1 | 同一业务集群所有副本必须一致 |
| LOGIN_ACCOUNT_LIMIT | 15 | 一个窗口内账号名及真实账号编号各自的尝试上限 |
| LOGIN_SOURCE_LIMIT | 120 | 连接来源的尝试上限 |
| LOGIN_GLOBAL_LIMIT | 300 | 集群总尝试上限，限制随机来源和随机账号的Redis键增长 |
| LOGIN_WINDOW_SECONDS | 60 | 计数窗口；从该计数首次尝试起计算 |
| LOGIN_PARALLELISM | 4 | 同时执行的登录上限；本机及Redis共享租约两层约束 |
| LOGIN_LEASE_SECONDS | 120 | 异常退出后的并发租约回收时间 |

Redis使用服务端时间和同一哈希槽的Lua脚本。拒绝返回429及Retry-After；Redis故障返回503，不退化为无限登录。许可在所有返回和异常路径释放，释放Redis失败时由租约保守回收。

默认明确关闭Spring转发头处理，只信任真实连接地址，不信任客户端X-Forwarded-For。反向代理后来源会汇总到代理地址，需要在入口增加可信代理及来源限速设计，按真实校园登录峰值调整参数；不能简单信任任意转发头。网关还应限制连接数、请求体和空闲时间。已登录会话不消耗登录预算。

## 素材存储

V6迁移新增media_storage_usage、media_storage_cleanup及media_asset.storage_state。现有素材按实际登记大小回填，每个素材至少计8192字节，同时限制文件数。管理员为教师任务上传时按任务的真实负责人记账，浏览器不能指定记账学校或负责人。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| STORAGE_OWNER_BYTES | 1073741824 | 每位负责人的累计计费字节，1GiB |
| STORAGE_SCHOOL_BYTES | 10737418240 | 每所学校累计字节，10GiB |
| STORAGE_GLOBAL_BYTES | 107374182400 | 业务库关联的所有素材累计字节，100GiB |
| STORAGE_OWNER_FILES | 10000 | 每位负责人的文件数量上限 |
| STORAGE_SCHOOL_FILES | 50000 | 每所学校文件数量上限 |
| STORAGE_GLOBAL_FILES | 500000 | 所有素材数量上限 |
| STORAGE_MINIMUM_FREE_BYTES | 2147483648 | 素材卷至少保留2GiB空闲空间 |
| STORAGE_PENDING_SECONDS | 900 | 中断预留的回收等待时间 |
| STORAGE_CLEANUP_DELAY_MS | 30000 | 回收任务间隔 |

全局账本行锁串行核验并预留全局、学校及负责人额度，随后写入文件；PENDING不可见，完成原子文件替换后标记READY。配额不足413，卷容量低于水位507，存储故障503。单文件大小限制继续有效。

数据库状态与固定条带文件锁共同阻止暂停写入与回收交错。锁文件永久保留且数量固定，避免删除锁文件造成两个不同文件实体同时被持锁。全部后端副本必须访问同一素材卷、同一锁文件实体，底层文件系统必须支持跨进程字节区间排他锁和原子移动。独立本地卷、多地域共享数据库、对象存储及不能保证锁语义的共享卷不属于本次验收范围，不能按当前实现直接扩容。

删除先经头像、作业等外键引用保护，成功后保留清理账本。物理文件和部分写入文件确认移除后才释放额度。失败的删除和中断上传继续计费，由后台重试；客户端删除遇到503后，素材可能已从列表隐藏，不能据此手动减账。重复回收不重复释放。删除学校或账号前同样需要先完成素材生命周期，禁止用裸SQL绕过账本删除素材。

上线前停止旧后端和边缘写入，备份业务库、素材及Outbox，盘点数据库登记素材与卷内文件是否一致。V6只能回填登记素材；旧版本遗留的孤儿文件必须先盘点并受控清理或登记。发现丢失文件、大小不符、负账或回收持续失败时停止新上传，核对备份和账本，禁止为了恢复上传而清零计数。已有素材超过新配额时保留数据并拒绝新增。

配额只覆盖Java原始素材。Java报告与推理产物、边缘缓存、日志、备份的总配额和保留期尚未完成。空闲水位是素材上传保护，不是整个主机的磁盘隔离；生产必须另配独立卷/系统配额、监控和告警。

## 视频资源隔离

VIDEO任务的模型加载、VideoCapture、采样、姿态推理和FFmpeg编码全部在独立进程中执行。父进程先建立资源限制，再通过标准输入握手授权处理。工作进程只拿本地受控路径及请求，不继承业务数据库或内部服务凭据。仍不接受HTTP提交任意命令、绝对路径或远程URL。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| VISION_VIDEO_TIMEOUT_SECONDS | 90 | 整个子进程作业墙钟期限，包括加载、解码、编码和管道写入；允许5至110秒 |
| VISION_VIDEO_MEMORY_MB | 2048 | Windows整个作业的提交内存预算；Linux每进程地址空间限制；允许256至8192MiB |

Windows以挂起方式创建进程，先分配Job Object，再恢复初始线程，防止虚拟环境启动器抢先派生实际解释器。Job约束作业总提交内存和最多4个进程（包括虚拟环境重定向器），关闭句柄时终止全部后代。作业分配或线程恢复失败则拒绝启动处理，不降级。Linux使用独立会话/进程组、RLIMIT_AS、RLIMIT_CPU以及父进程的墙钟期限；超时终止整个进程组。Linux限制按进程继承，不能当作整个容器的内存总量限制，生产还必须配置cgroup内存/进程数/CPU限额并实机验证。其他平台拒绝视频隔离处理。

超时、进程资源拒绝及隔离失败返回503，损坏或超范围输入返回422。结果暂存于单独目录，父进程验证请求绑定、结构、产物大小及SHA-256，先发布视频、最后发布元数据。没有元数据的产物不能下载；失败清理临时目录。相同作业编号绑定不同输入仍拒绝，成功结果可以幂等重放。图片和虚拟摄像头路径保留现有有界校验，未宣称获得视频作业相同的进程内存隔离。

Windows边界已在本机执行验证。Linux代码与CI测试入口已加入，尚无本轮Linux或远端GitHub执行证据。新增视频进程重复加载权重会增加内存和延迟，不能据本机样例推算多节点容量。

实现依据：[Microsoft作业扩展限制](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information)、[Microsoft作业基础限制](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information)、[Python资源限制](https://docs.python.org/3.12/library/resource.html)、[Python子进程超时与回收](https://docs.python.org/3.12/library/subprocess.html)。
