# CPU、GPU 与华为昇腾 NPU 推理配置

日期：2026-11-04。

## 配置入口

人物检测和姿态模型共用服务级设备配置，切换后重启视觉服务。浏览器请求不能选择设备，Java、edge 的接口不变。未配置时使用 CPU。

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `VISION_DEVICE` | `cpu` | `cpu`、`gpu`、`npu`，使用小写 |
| `VISION_DEVICE_ID` | `0` | GPU/NPU 在当前进程可见设备中的编号，0至255；CPU只允许0 |
| `VISION_CPU_THREADS` | `2` | ONNX CPU线程预算，1至8；不是并发课堂数 |

| 模式 | ONNX Provider | 独立环境 | 当前验证 |
| --- | --- | --- | --- |
| CPU | CPUExecutionProvider | `fastapi/.venv` | 本机真实图片及隔离视频通过 |
| NVIDIA GPU | CUDAExecutionProvider | `fastapi/runtimes/gpu/.venv` | 锁文件、配置及错误路径通过，未测硬件 |
| 华为昇腾 NPU | CANNExecutionProvider | `fastapi/runtimes/npu/.venv` | Linux锁文件、配置及错误路径通过，未测硬件 |

设备配置控制YOLOX与RTMPose的模型计算。OpenCV抽帧、图片/视频解码、模型前后处理、绘制和FFmpeg编码继续在CPU。30秒、32MiB、32采样帧和每帧16人上限保持；当前没有GPU解码或昇腾DVPP视频处理。

## 根目录统一启动

使用根目录`python scripts/local_dev.py vision`时，在根`.env.local`增加：

```dotenv
VISION_DEVICE=cpu
VISION_DEVICE_ID=0
VISION_CPU_THREADS=2
```

GPU改为`VISION_DEVICE=gpu`；昇腾改为`VISION_DEVICE=npu`。`REAL_DEMO_ENABLED=true`与已校验模型仍是启用真实模型的前提。启动工具仅将这些配置转发给vision，不转发给浏览器、Java、edge或AI服务。未设置设备时保留原CPU启动方式。

CPU运行`uv run --frozen`；GPU/NPU运行`uv run --frozen --project runtimes/gpu`或`runtimes/npu`，从各自锁文件创建环境，不自动修改CPU环境。修改配置后应停止原视觉服务再启动，避免5000端口冲突；不要求清空原有任务或素材。

## 独立启动与IDEA

不使用根启动工具时，在`fastapi/.env`配置`VISION_ENGINE=onnx`、设备参数、内部凭据及模型/素材/结果路径。路径可采用绝对路径，凭据不写入公开文件。

CPU：

```powershell
Set-Location 'D:\self\uu_smart_classroom_cv\fastapi'
uv sync --frozen
uv run --frozen python -m classroom_vision.server
```

GPU：先安装与锁定运行时兼容的NVIDIA驱动、CUDA和cuDNN，并让操作系统加载器可找到运行库，再执行：

```powershell
Set-Location 'D:\self\uu_smart_classroom_cv\fastapi'
uv sync --frozen --project runtimes/gpu
uv run --frozen --project runtimes/gpu python -m classroom_vision.server
```

昇腾：本轮锁定`onnxruntime-cann==1.24.4`的Linux发行包，需要实际昇腾服务器、相应架构Python 3.12、驱动/固件及兼容CANN。当前Windows本机不能直接验证该环境。在Linux的fastapi目录、按厂商安装说明加载CANN环境后执行：

```bash
uv sync --frozen --project runtimes/npu
uv run --frozen --project runtimes/npu python -m classroom_vision.server
```

GPU环境锁定`onnxruntime-gpu==1.31.1`，NPU环境锁定`onnxruntime-cann==1.24.4`；默认CPU锁文件保持不变。三个发行包提供同一个`onnxruntime`模块，因此加速环境显式排除CPU发行包，且继续只安装`opencv-python-headless`。不要在同一个环境中逐个安装三个发行包。

IDEA仍标记`fastapi/src`为Sources，working directory为`fastapi`，模块入口为`classroom_vision.server`。CPU解释器选`fastapi/.venv/Scripts/python.exe`；Windows NVIDIA选`fastapi/runtimes/gpu/.venv/Scripts/python.exe`。昇腾需要Linux远程解释器`fastapi/runtimes/npu/.venv/bin/python`，IDE功能不支持远程Python时通过Linux终端启动。原生调试需显式传入设备、模型、路径和凭据变量，不会自动读取根`.env.local`。

## 运行时核验与失败方式

在选定环境中先核对Provider：

```bash
# CPU省略--project；GPU将npu替换为gpu。
uv run --frozen --project runtimes/npu python -c "import onnxruntime as ort; print(ort.__version__, ort.get_available_providers())"
```

Provider出现在列表中仅代表运行包声明了该后端。服务还会实际创建两个模型会话，校验首选Provider并关闭运行时回退；驱动、设备或算子失败会拒绝启动/执行，不能凭列表宣称硬件可用。ORT可能额外注册未使用的CPU Provider，是否有CPU算子由禁止CPU回退的会话选项控制，不能仅凭注册列表判断。运行日志记录选择的设备、编号及Provider。

- 缺少CUDA/CANN Provider时明确报设备不可用，安装CPU包不会假装加速成功。
- 加速会话禁止CPU算子回退及`session.run()`重试回退。昇腾禁用子图CPU回退和模型调试文件转储，采用`must_keep_origin_dtype`精度设置。模型若有不支持算子，需要重新导出/适配并验收，不能自动放宽到CPU混合执行。
- 视频子进程继承设备编号，以及限定的CUDA/CANN库路径和可见设备变量；NPU还保留运维通过CANN set_env.sh加载的PYTHONPATH算子目录和TOOLCHAIN_HOME，项目src排在前面。只从可信安装目录加载驱动环境，Python算子依赖须与Python 3.12匹配。内部令牌及数据库配置不继承。子进程与父进程使用同一个环境，不会再隐式创建CPU模型会话。
- 切换设备或设备编号后请提交新作业。缓存校验拒绝将旧CPU结果当作NPU/GPU执行结果，历史CPU缓存继续可读取。

## 容器与真实设备验收

当前`fastapi/Dockerfile`及已验证候选镜像只带CPU运行时。staging模板可转发设备参数，但加速部署还必须构建匹配平台的镜像，安装对应独立锁文件环境，配置GPU runtime或昇腾设备/驱动挂载、非root设备访问、可写缓存/日志目录及安全扫描。没有生成已验收的GPU/NPU生产镜像。

现有视频子进程仍保留主机内存/虚拟地址空间、CPU时间、文件体积、进程树和墙钟超时限制；它们不等于显存/昇腾设备内存配额。驱动可能映射较大虚拟地址空间，默认2GiB限制也可能拒绝加速任务。目标硬件需实测这些边界，必要时设计独立、经验证的加速作业容器/cgroup方案；本轮不绕过原安全限制。

上线前必须在具体Ascend卡型、CANN/驱动/固件组合上验证两个模型、短片子进程、超时退出后的设备内存回收、下一任务恢复、结果与CPU的偏差、真实课堂精度及整链路吞吐。仅建立会话、单元测试或CPU示例不能替代这些验收。

官方参考：[CUDA Provider与兼容要求](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html)、[华为CANN Provider](https://onnxruntime.ai/docs/execution-providers/community-maintained/CANN-ExecutionProvider.html)、[CANN运行包](https://pypi.org/project/onnxruntime-cann/)。截至本次核查，官方CANN页面的兼容表示例未覆盖锁定包的所有新版本，不能直接套用旧版矩阵给目标机器下结论，需结合所选发行包与厂商验证。
