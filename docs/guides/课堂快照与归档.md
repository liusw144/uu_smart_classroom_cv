# 课堂快照、实际时间与归档

日期：2026-11-04。本指南对应V11与V12迁移和本批前后端代码，不代表生产发布或本机业务库已升级。

## 在页面使用

1. 创建课堂任务时选择课程，可填写计划开始、计划结束及教室名称。计划结束必须晚于开始；教室名称当前仅作记录，尚未绑定摄像头。
2. 点击“查看”可看到创建当时的课程、班级、年级、教务人数、学期与负责人显示名。之后修改教务目录，不会刷新该课堂快照。
3. 未开始且从未产生分析/报告的计划课堂可编辑；更换为其他课程时重新捕获快照。重新选择不同负责人的课程会拒绝，教师交接另走后续授课授权流程。
4. 使用“开始课堂”“结束课堂”记录实际过程；选填实际时间，未填使用当前服务时间。历史待确认课堂补记开始时必须填写真实开始时间。实际时间不能是未来，结束必须晚于开始。
5. 已结束课堂可以归档；待确认历史课堂也可直接归档而保留未知实际时间。仍有等待/执行中作业时，先完成或取消作业再归档。
6. 归档后课堂、检测结果和报告保留为只读历史，不能新增或删除分析/报告。未归档时删除分析记录，也不会重新解锁已使用课堂的资料或删除权限。

课堂状态与检测状态分别管理：“课堂已结束”不等于录像已分析，“检测成功”也不会自动证明一堂课的真实起止时间。

## 历史初始化说明

旧数据没有保存原始教务快照。V11只能按升级时现值初始化，标为LEGACY_BACKFILL，状态为历史待确认，不声称恢复了开课时资料。页面和由此生成的教务报告均保留来源、记录时间与说明。

新课堂标为CREATED；计划阶段显式换课程标为REASSIGNED。操作事件记录操作人员、服务记录时间、状态与版本，数据库保留该版本上下文。实际授课时间与事件操作时间是不同字段。

## 接口与并发

- 原GET/POST/PUT `/api/v1/tasks`入口保留；增加`scheduled_end_at`、`room_name`、`version`以及响应中的`snapshot`、`status`、`metadata_locked`和实际时间。
- 新增POST `/api/v1/tasks/{id}/transition`，参数为`action=START|COMPLETE|ARCHIVE`、必填`version`和可选`occurred_at`。
- 新增GET `/api/v1/tasks/{id}/events?page=1&size=20`，沿用学校/负责人范围。
- 新界面将版本与打开表单时的数据一起保存；刷新列表或翻页不会自动替换编辑版本。旧PUT客户端可省略version以保持输入兼容，但新集成应始终传version以获得过期修改保护。
- 关键资料冻结和归档判断在课次行锁内完成。新增/删除检测、教务报告和AI报告使用同一课次锁，禁止并发穿透归档；有分析历史的永久冻结标记不会随记录删除消失。
- 400表示字段或时间不合法；409表示版本/状态/归档/引用冲突；无资源访问权返回404，平台运维仍无默认课堂数据权限。

## 升级要求

新增V11教务快照/状态/事件及V12永久冻结；未修改既有V1至V10。本轮已在uu_classroom_test和新建合成历史库验证，临时库已移除，本机业务库未执行升级。

业务环境需要按[运维命令](../harness/commands.md)和[候选部署指南](../../deploy/staging/README.md)安排维护窗口：停止相关写入、取得数据库和媒体一致备份，再切换后端/前端并由Flyway升级。旧后端不能继续按V10字段写入升级后的课堂表，因此本批不能让新旧后端混跑写入。不要把测试库的DDL/清理命令用于业务库。

本轮没有演练该版本的业务库升级/回滚，也未重建已运行的候选容器。源码验证完成后，仍需执行相应安装、恢复和发布验收。
